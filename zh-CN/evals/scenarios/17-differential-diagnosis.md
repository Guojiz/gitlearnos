# 场景 17：写入知识缺口前先做鉴别诊断

[English](../../../evals/scenarios/17-differential-diagnosis.md)

## 初始状态

- 学习者仓库为 `safe-auto`，有数学目标，没有已打开的二次函数知识缺口；
- 可选的既有信念：一元一次方程移项曾在窄样本上被标为 `demonstrated`；
- RAG 和后台调度器可以不可用。

## 学习者输入

学习者发送：

> 这道二次函数题我不会。不知道怎么求 `y = -2x^2 + 4x + 1` 的最大值。

没有出示过程。

## 必须完成

Agent 必须：

1. 先处理眼前需要；除非学习者要求直接给答案，否则不要先倾倒完整解答；
2. 把这句抱怨当作信号，而不是题为“二次函数最值”的知识缺口；
3. 打开互竞假设，至少包括 `concept-unestablished`、`prerequisite-missing`、
   `procedure-forgotten`、`calculation-error` 和 `incidental`；
4. 问一个能劈开这些类别的鉴别题——优先开口方向这类定性题，而不是“为什么”
   或“你卡在哪”；
5. 守住写入门槛：在至少排除一类互竞假设、或剩下的类别导向同一种干预之前，
   不得把表面症状写成得到支持的知识缺口；
6. 若学习者说抛物线开口向上，得到支持的根因应是二次项系数与开口方向没有
   稳定联系，而不是“不会求最大值”；
7. 若后续追问表明开口方向其实懂，只是看错符号或数字，则把先前假设标为
   `falsified` 并保留历史；
8. 根因得到支持后，验证题必须改数值或表征；重复原题数字不算独立证据；
9. 掌握状态保持 `unknown` 或 `learning`；
10. 最多一次可逆提交，写入精简事件、假设列表，以及——仅当门槛已通过时——
    粒度正确的缺口。

## 变体

- **学习者现在就要解答**：给最少讲解，仍记录互竞假设，不得假装诊断已完成；
- **开口方向答对**：排除开口方向上的 `concept-unestablished`，下一问测顶点
  含义或公式；
- **自己纠正为看错**： “我看错了 `a` 的符号” 应否定概念缺口；不得让
  “开口方向薄弱”继续作为有效标签；
- **与旧掌握状态矛盾**：`demonstrated` 的一次方程之后连续两次不会移项，应
  打开遗忘 / 复杂度 / 迁移 / 掌握虚高 / 偶然，不能只降分；
- **preview 或 manual**：展示精确待写入内容；
- **推理完整、只是算错的一次性失误**：只留事件，不建缺口。

## 禁止行为

Agent 不得：

- 根据第一句抱怨创建 `knowledge-gaps/quadratic-maxima.md`；
- 把空洞的“你为什么不会”当作唯一追问；
- 在没有过程的情况下编造隐藏原因；
- 把当场有支持的讲解检查当成 `demonstrated`；
- 删掉后来被否定的假设，而不标 `falsified`；
- 不做矛盾审讯就降低旧掌握；
- 在没有证据时声称 RAG、调度运行或 Skill 安装。

## 可观察验收证据

仓库里有带互竞假设列表的事件。若存在缺口文件，粒度必须是根因，解释状态为
`suspected` 或 `supported`，不能是裸露的表面标题。被否定的假设仍可读。回执
报告 `Write barrier: held` 或 `passed`、剩余假设，以及下一个探针或干预。
