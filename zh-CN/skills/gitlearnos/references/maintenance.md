# GitLearnOS 维护

遵循 Router 的核心契约。本参考文件可以修复确定性状态，但不得编造证据或
改写应保留的学习者记录。

作为必需的重复 `maintenance` 任务运行时，使用 `gitlearnos.yml` 和
`automation.md` 中配置的本地时间与调度状态。没有待处理输入或实质变化时，
标记 `skipped`：不通知、不修改最后运行时间，也不提交。

[English source](../../../../skills/gitlearnos/references/maintenance.md)

## 检查顺序

1. `gitlearnos.yml` 与运行时的真实能力；
2. 根仪表盘、学科索引和当前学科目标；
3. 当前学科中未处理的收件箱内容和等待中的交接；
4. 活跃知识缺口，以及“问题解决”与“掌握”的区分；
5. 已计划、已到期和未评分的问题；
6. 来源与模型链接；
7. 等待归纳或迁移检查的重复解题证据；
8. 重复、过期、孤立或过量的状态。

## 高价值检查项

- 仪表盘复制状态而不是链接状态；
- 学科状态放在根目录或错误的学科文件夹中；
- 同一事件在多个学科中存在重复副本；
- 已由教师解决的事项仍显示为 AI 教学任务；
- 把问题已解决误当作已证明掌握；
- 未有作答的生成题集却显示为已完成；
- 问题过于笼统、重复或没有评分标准；
- 重复输入创建了重复文件；
- 同型观察仍然彼此复制或孤立，没有建立链接；
- 模型由一次含糊事件晋升，或没有证据链接；
- AI 诊断被写成学习者报告的事实；
- 答题模板只是复制一道完整答案；
- 晋升模型没有新迁移检验，或从未改变后续行动；
- 只有提示词或日期，却声称自动化已经建立；
- `safe-auto` 对低风险操作反复请求确认；
- 超出策略需要保留个人原始材料或身份信息；
- 学习者无法知道代理改了什么，或无法撤销代理事件。
- 必需的重复整理或出题没有明确本地时间、IANA 时区、提供方任务 ID 或验证证据；
- 两个调度来源可能交付同一个到期发生项；

## 直接修复

在 `safe-auto` 下，直接修复明确的链接、重复视图、过期仪表盘状态、确定性日期、过时的非关键任务和矛盾。保留来源链和用户内容。

删除、广泛重构、改写笔记、更改策略、发布、可见性变化、敏感身份、密钥或许可证变化前必须询问。

撤销时，先识别最近一个确切的代理创建事件或原子提交，并确认其中不含无关的用户工作，再使用当前可用的最安全、可逆机制。若范围混杂，停止并询问。

计划运行时，根据 `maintenance` 与计划发生时刻生成幂等键，取得唯一写入锁或
租约，并在写入前立即比较 Git 基础版本。发生并发变化时停止。错过的发生项最多
补跑一次。最多创建一个提交，且只有学习状态实质变化时才提交。
