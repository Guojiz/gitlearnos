# Skill、记忆与状态

GitLearnOS 将行为、长期状态和临时上下文分开。

```text
Skill 或仓库规则
→ Agent 应该怎样行动

目标仓库
→ 当前可检查学习状态

AI 原生记忆
→ 激活指针、稳定偏好与长期模式的可选缓存

当前对话或工作区
→ 临时执行空间
```

## 具备工具能力的 Chat 或 Work 路径

当 Chat 或 Work 对话能读取来源并写入目标仓库时：

1. 判断输入是否为候选学习事件；
2. 可用时加载 Router，否则使用正式仓库或项目规则；
3. 只检查活跃目标状态；
4. 先处理当前请求；
5. 有用时直接整理输入或生成针对性问题；
6. 将配置授权的状态变化写入唯一状态文件；
7. 只有激活指针、稳定偏好或长期模式改变时，才更新原生记忆。

不能让原生记忆成为学习状态的唯一副本。当前获授权 Runtime 能修改文件时，也不要让用户手工复制。

## Skill 路径

安装完整文件夹，不能只安装入口文件：

```text
skills/gitlearnos/
```

Codex 与 OpenCode 默认使用 `.agents/skills/gitlearnos/`；Claude Code 使用
`.claude/skills/gitlearnos/`。运行环境先看到唯一 Router 元数据，再加载一个
操作参考文件，确有必要时最多再加载一个学科参考文件。Skill 保存行为，不保存
持续变化的个人状态。

当前运行环境真正列出 `gitlearnos` 且能打开打包参考文件前，源文件夹只能算
`source-only`。见
[Agent 适配器](../adapters/agents/README.md#不同-agent-如何发现-skill)。

使用一个主 Agent。加载不同 Skill 不代表拆分 Agent。

Skills 是可选项。当前 Chat 界面不提供 Skills 时，`AGENTS.md`、项目指令、记忆与事件识别必须保留相同行为。

## 仓库指令路径

如果不支持自定义 Skills，使用 `AGENTS.md` 作为仓库约定。当前界面无法发现
仓库指令时，把经过适配的
[`templates/project-instructions.md`](../../templates/project-instructions.md)
放入项目指令或自定义指令。不要用“读取全部文档”来补偿。

这份精简指令必须在没有 Skill 时独立保留：

- 常驻识别与先回答行为；
- 整理、出题、复测、辅导、来源、模型和维护路由；
- `safe-auto`、`preview` 与 `manual` 的有效权限；
- 保留原始证据，并只用间隔后的独立作答证明掌握；
- 工具缺失时提供诚实回执与待写回内容。

这是有意的核心重复，不是第二套协议。`GITLEARNOS.md` 仍是正式协议；单一
Skill 包保存按需加载的详细参考文件；项目指令保存最小、常驻的行为。

## 原生记忆

适合保存：

- 稳定语言与讲解偏好；
- 长期目标；
- 长期隐私限制；
- 多次证据支持的重复模式；
- 选择哪个目标仓库作为唯一状态的规则；
- GitLearnOS 已启用，并应注意隐式学习事件；
- 当前项目或仓库指针。

默认不保存：

- 一次性错误；
- 到期日期与临时任务；
- 原始私人笔记；
- 不完整来源；
- 未验证假设；
- 完整复习历史。

使用精简的
[`templates/native-memory-pointer.md`](../../templates/native-memory-pointer.md)
条目，不要让记忆保存完整 Skills。这个指针应在后续对话中唤醒项目指令或仓库
读取。

请求更新记忆后，把结果分为 `saved`、`suggested`、`unavailable` 或
`unknown`。只有运行环境提供了足够证据，能够验证保留的指针与目标时，才能
使用 `saved`。记忆生成或回忆可能延迟，因此起草条目不等于已经保存。

## 冲突规则

原生记忆与仓库状态不一致时：

1. 检查时间与证据；
2. 确认哪一层过时；
3. 明确更新；
4. 无法判断时记录不确定性，不能静默选择方便的版本。

## 回退

单上下文或只读环境只提供一次任务需要的文件，并输出待写回区块。写入目标仓库后再恢复长期连续性。大型来源文件留在持久项目来源区或获授权的本地文件夹。
