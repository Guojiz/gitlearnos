# GitLearnOS 学习者仓库

本仓库保存由学习者拥有的状态。遵守 `gitlearnos.yml` 声明版本对应的
GitLearnOS 协议。

开始操作前：

1. 阅读 `gitlearnos.yml`、`learning-policy.md` 和 `dashboard.md`；
2. 读取当前学科目标，以及本次确实需要的已链接证据；
3. 即使学习者没有提 GitLearnOS 或调用 Skill，也把学科问题、作答、错误、
   拍摄页面、笔记、反馈和结果视为候选学习事件；
4. 检查当前 Git 版本并保留无关工作；
5. 先解决学习者眼前的需要；
6. 同时根据 `gitlearnos.yml` 和 `learning-policy.md` 判断有效写入权限；两者
   冲突或含糊时采用更严格的一项；
7. 有效模式为 `safe-auto` 时，事件有明确长期价值才做最小更新；`preview`
   时只展示拟议改动，不写入；`manual` 或政策禁用自动写入时，等待明确批准，
   或返回精确的待写回内容；
8. 保留原始作答、笔记与外部反馈；
9. 只有有效权限允许写入时，才为一个有意义的学习事件提交一次，并返回诚实
   回执。

自定义 Skills 不可用时，直接根据本指令继续工作。使用最小的匹配核心操作：

- 整理证据、反馈或笔记；
- 根据当前目标或薄弱点生成有依据的问题；
- 评阅尝试作答，不猜测掌握状态；
- 当前请求帮助时进行讲解或引导练习；
- 处理来源可追溯性，大型原文件默认不放进 Git；
- 只根据证据修订可复用模型；
- 修复过期状态、重复、链接或待写回内容。

这些指令已经定义核心操作时，不要要求学习者先调用或安装 Skill。若当前界面
无法发现本文件，就在项目指令或自定义指令中使用对应的
`templates/project-instructions.md` 内容。

不要保存普通聊天，不要编造无法访问的证据，也不要在未经验证时声称完成远程
push、后台调度、跨对话记忆或证明掌握。输入只是临时、含糊或无关内容时，
不能仅因本仓库存在就保存。
