# GitLearnOS 出题

遵循 Router 的核心契约。本参考文件只细化问题选择和持久化方式，不重新定义
掌握或写入权限。

[English source](../../../../skills/gitlearnos/references/question.md)

## 目标

生成下一组有用的问题，而不是堆积通用题量。支持两种一等输出：

1. 供学习者回答的问题；
2. 学习者可以带给外部帮助者的问题。

作为必需的重复 `due-review` 任务运行时，使用 `learning-policy.md` 中配置的
本地时间、时区、安静时段、渠道与最大题量，以及 `automation.md` 中已验证的
调度状态。没有到期证据时标记 `skipped`：不生成凑数题、不通知、不提交。

## 隐式触发

学习者的学科问题既是当前请求，也可能是学习证据。先按要求回答或引导，再判断它是否显露了持久缺口、有用来源，或值得安排一次新检查。不要在每个随口问题之后都强行生成测验。

若当前目标和目标仓库明确，在 `safe-auto` 下可以直接生成并保存有用的下一题，不必等待“考考我”。相关性或目标难度不明确时，只给一个精确的下一题，或只问一个必要问题。尊重“只回答”“不要复习”和疲劳状态。

## 读取

```text
当前目标
+ 学科路径
+ 相关来源或模型
+ 已链接的知识缺口
+ 最近已作答问题及支持程度
+ 学习者约束：数量、时间、格式、难度
```

若必要来源不可用，请索取最小片段，或把结果标记为基于通用知识生成。

## 选择目的

- `diagnostic`：定位失败点；
- `practice`：巩固方法；
- `variation`：改变数字、表示或表面形式；
- `transfer`：在新情境中应用概念；
- `review`：延迟提取；
- `exam`：模拟所需条件；
- `handoff`：向教师、导师、同伴或另一智能体提问。

不要混合多个目的，除非说明原因。

## 生成学习者问题

每个持久化题集都要记录目标、依据、问题、答案或成功条件以及状态。`track`、`need`、难度、时间、选择理由和新颖性，只有能改善后续执行时才添加：

```yaml
purpose:
subject:
grounded_in:
target_goal:
target_gap:
track: school | self-study | mixed
need: current-course | remediation | exam | exploration | advance | project | research | skill
difficulty:
estimated_time:
selection_reason:
novelty:
questions:
answer_key_or_rubric:
status: planned
```

规则：

- 学习者未要求更大题集时，优先生成 1–5 道聚焦问题；
- 改变结构，而不只是数字；
- 验证时不要复制完全相同的例题；
- 采用适合学科的回答形式：解答、证明、代码、解释、回忆、比较、批评或创作；
- 提供足够的答案或评分标准，让后续智能体能一致评分；
- 除非学习者要求，否则作答前隐藏答案；
- 只持久化已布置、已作答或可复用的题集。

当前回答中已经交付或布置的问题不是临时草稿。在有效 `safe-auto` 且具备写入和
Git 能力时，结束回答前必须：

1. 把完整题集写入 `subjects/<subject>/reviews/`，状态为 `planned`；答案键或
   评分标准保存在文件中，但不能出现在给学习者看的问题里；
2. 从目标缺口链接题集；若学习者当前陈述是已有模式的新观察，还要更新重复证据
   数量；
3. 刷新 `dashboard.md`；没有调度器时，忠实记录到期或 `on-handoff` 检查；
4. 暂存全部改动文件，把完整出题任务作为一个可逆学习事件提交。

具备这些能力时，不能只在聊天中留下已布置问题。处于 `preview` 或 `manual` 时，
返回精确待写内容，不能声称已经持久化。

### 学习轨道适配

- `school`：匹配已授范围、教师方法、必需记号与评估格式；与当前要求不同的高级捷径必须标明；
- `self-study`：在有用时加入概念深度、开放解释、创作、项目和更广泛迁移；
- `mixed`：修补学校目标的先修知识，同时保留学习者更广的自主学习路径。

### 需求与学科适配

- 事实学习：提取、辨别、解释、延迟回忆；
- 数学和科学：推导、解题、证明、表示、迁移，以及在容易混淆的题型中做出区分；
- 语言：理解、产出、纠错、对话、风格；
- 编程：实现、测试、调试、审查、解释；
- 阅读和研究：提取主张、比较证据、批评、综合、开放问题；
- 项目和实用技能：里程碑、受约束任务、演示、作品评分标准、复盘。

只有可观察表现适合 0–3 量表时才使用它。否则定义测试、评分标准、里程碑或其他明确成功条件。

## 生成外部提问包

在 `subjects/<subject>/handoffs/` 下创建，包含：

- 目标渠道或去向，不记录不必要的身份；
- 目标和来源定位；
- 原题或安全引用；
- 学习者尝试；
- 确切卡点；
- 给帮助者的聚焦问题；
- 期望反馈类型；
- 反馈与协调字段。

已链接知识缺口保持 v2 的解决状态词汇：

- 问题只是转交出去时使用 `open`；
- 等待反馈或后续验证时使用 `needs-check`；
- 在交接文件中记录去向、送达和回复进度。

刷新仪表盘，但不要把交接进度复制为第二套缺口状态。

## 根据证据调整

- 错误或高度依赖帮助：缩小范围并诊断；
- 部分完成：使用接近的变式或小范围迁移；
- 独立成功：使用延迟提取或更广迁移；
- 外部已解决但未证明掌握：生成可选的简短检查，而不是完整重教题集；
- 多次成功：降低频率并避免重复问题。

模型由重复问题归纳而来时，既要验证是否识别，也要验证能否执行。改变结构、
表示或语境，不能只换数字，让学习者必须选择正确模型。若证据表明薄弱点在于
选择方法，可混入一个容易混淆的相邻题型。练习仍应保持在能有效完成的小范围；
学习者尚不能执行基础方法时，不能以交错练习为由让其过载。

出题本身不能证明学习。未作答题集保持 `planned`。
计划交付时只发送题目正文与选择理由；答案键或评分标准保留在获授权的仓库状态中，
供之后评分。根据计划发生时刻与到期证据使用幂等键，让补跑和接手执行不能重复
交付同一题组。发生并发 Git 变化时停止，不能 rebase 或覆盖。
