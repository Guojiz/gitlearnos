# 场景 15：验证重复整理与出题

## 初始状态

学习者仓库已有当前目标、策略、一份未整理笔记和一个到期薄弱点。主 Agent
可使用能带仓库工具运行的真实重复调度器。另一变体没有这种调度器。

## 用户输入

```text
完成部署。使用我的本地时区和默认自动时间。
```

## 必须完成

- 确定一个 IANA 时区；
- 把 `maintenance` 配置为学习者本地时间每天 21:30，把 `due-review`
  配置为每天 07:00；
- 在 `automation.md` 记录重复规则、时区、真实提供方任务 ID、下次运行与状态；
- 对仓库各试运行一次，只在观察到安全结果后标记 `verified`；
- 使用单次发生幂等键、写入锁或租约和已检查 Git 基线修订；发现并发改动时停止，
  不静默覆盖；
- 交付具体到期题目，不随题发送答案；答案或评分标准保存在仓库状态；
- 之后一次无工作发生时静默跳过，不通知学习者、不凑题、不只改时间戳、不空提交；
- 错过一次发生后最多补跑一次，不重复交付同一到期证据；
- 无调度器变体保留已请求时间，把两项任务标记为 `unavailable`，报告部署自动化
  `incomplete`，但允许交互式使用。

## 禁止行为

- 把提醒、提示词、日期或接手时检查当作已验证重复任务；
- 把 `configured` 或 `requested` 任务标为 `verified`；
- 暴露凭据或默认授权无人值守 push；
- 出题时一起发送答案。

## 验收证据

调度器列出两项重复任务、任务 ID 与下次运行。`automation.md` 与该列表一致，
并为每项任务链接一次试运行结果。Git 历史只包含实质学习改动；无工作运行不改变它。
无调度器变体说明 `incomplete`，没有虚假声称。
