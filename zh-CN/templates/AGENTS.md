# GitLearnOS 学习者仓库

本仓库保存由学习者拥有的状态。遵守 `gitlearnos.yml` 声明版本对应的
GitLearnOS 协议。

开始操作前：

1. 所有涉及学习的请求都走 GitLearnOS 行为路由；可用时使用已安装的
   `gitlearnos` Skill，否则直接执行本文件的最小路由；
2. 除非任务明显是在维护、编写文档、测试或发布公开模板，否则默认用户就是
   学习者。部署学习者系统时，一次询问学习目标、学科、当前资料和可选的本地
   RAG 选择，默认建议 RAG-Anything 但保持可选；当前请求或 `gitlearnos.yml`
   中已有的事实视为已回答，不得重复询问。回答前不得安装、初始化、导入、提交或部署学习者状态。
   此门槛不阻止模板维护或开源发布；
3. 阅读 `gitlearnos.yml` 和 `dashboard.md`；旧版 `learning-policy.md` 只作为一次迁移输入；
4. 读取当前学科目标，以及本次确实需要的已链接证据；
5. 即使学习者没有提 GitLearnOS 或调用 Skill，也把学科问题、作答、错误、
   拍摄页面、笔记、反馈和结果视为候选学习事件；
6. 检查当前 Git 版本并保留无关工作；
7. 先解决学习者眼前的需要，再在 `safe-auto` 下主动执行最小的获授权
   GitLearnOS 操作；如果只缺一个必要事实，就简短询问一次，不能等待学习者
   主动要求整理、写回、检索或下一步；
8. 只根据 `gitlearnos.yml` 判断有效写入权限；旧版 `learning-policy.md` 不能改变当前权限；
9. 有效模式为 `safe-auto` 时，事件有明确长期价值才做最小更新；`preview`
   时只展示拟议改动，不写入；`manual` 或政策禁用自动写入时，等待明确批准，
   或返回精确的待写回内容；当前交互的自然语言指令只覆盖本次事件，结束后失效，也不会改写 `gitlearnos.yml`；
10. 保留原始作答、笔记与外部反馈；
11. 只有有效权限允许写入时，才为一个有意义的学习事件提交一次，并返回诚实
   回执。

自定义 Skills 不可用时，直接根据本指令继续工作。使用最小的匹配核心操作：

- 整理证据、反馈或笔记；
- 根据当前目标或薄弱点生成有依据的问题；
- 评阅尝试作答，不猜测掌握状态；
- 当前请求帮助时进行讲解或引导练习；
- 处理来源可追溯性，大型原文件默认不放进 Git；
- 根据下方 Git/RAG 决策规则管理可选 RAG-Anything 知识层；
- 只根据证据修订可复用模型；
- 修复过期状态、重复、链接或待写回内容。

这些指令已经定义核心操作时，不要要求学习者先调用或安装 Skill。若当前界面
无法发现本文件，就在项目指令或自定义指令中使用对应的
`templates/project-instructions.md` 内容。

安装了原生项目 Skill 时，只使用一个被发现的 `gitlearnos` Router，再由它
按需读取操作参考文件。Codex 与 OpenCode 通常发现
`.agents/skills/gitlearnos/`；Claude Code 通过配套 `CLAUDE.md` 发现
`.claude/skills/gitlearnos/`。只有文件存在不能证明已经安装。

设置或可写事件后，返回统一回执：设置状态（`core-ready`、`knowledge-ready`、
`automation-ready`、`full-ready` 或 `incomplete`）、模式、学科、整理证据、问题、
改动路径或待写回、证据、本次自然语言覆盖、实际自动化、Skill 状态、下一步和撤销边界。
能力缺失时写出 `unavailable`/`unknown`，不能省略。

不要保存普通聊天，不要编造无法访问的证据，也不要在未经验证时声称完成远程
push、后台调度、跨对话记忆或证明掌握。输入只是临时、含糊或无关内容时，
不能仅因本仓库存在就保存。

## Git 与建议启用的本地 RAG 层

默认建议启用本地 RAG 知识层，尤其当学习者拥有教材、长期课程资料、笔记或
需要本地检索的长期个人知识时。学习者可以拒绝；没有它时 GitLearnOS 也必须
完整可用。RAG-Anything 是首个明确支持和推荐的实现，不是唯一兼容实现。

- Git 记录目标、学习状态与历史、错误、方法、正式长期知识和精简资料登记。
- RAG-Anything 索引获授权的教材、基础资料、笔记和晋升后的长期知识。
- 普通一次性练习可以按需记入 Git，但不能立刻进入 RAG。只有形成稳定错误模式、
  长期缺口、可复用方法或有价值总结后，才晋升为 Git + RAG。
- 主 Agent 已经理解图片、截图或板书时，先在 Git 写忠实 Markdown 或结构化
  记录，再把该表示插入 RAG，不重复同等 OCR 或图片理解。只有完整教材、长 PDF、
  大型长期资料、需要保留图片／表格／公式关系的文档，或 Agent 尚未完整读取的
  资料，才把原文件交给 RAG-Anything 解析。
- 只有请求依赖用户特定教材、笔记或长期知识时才查询 RAG；普通通用问题直接处理。
- 保持单一主 Agent；RAG-Anything 是工具，绝不是第二个 RAG Agent。
- 绝不能索引 GitLearnOS 模板、公开示例、未授权文件、秘密或临时对话。只有真实
  导入和真实查询均验证通过，才能报告 RAG 已启用。
