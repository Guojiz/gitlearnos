# 运行环境自适应

GitLearnOS 保存可移植政策与状态，当前主 AI 提供执行能力。

## 检测能力，不只看品牌

```text
能读模板？
能读写目标仓？
能访问授权来源？
能加载文件型 Skills 或仓库规则？
能原子写入或访问版本历史？
有原生记忆？
有项目指令或自动发现的仓库说明？
有真实调度器？
哪些步骤确实必须由用户完成？
```

安全时直接测试。产品名称不能证明权限。

## ChatGPT Chat 与 Work 路径

只要当前 ChatGPT 项目或会话真正具备所需仓库工具，Chat 与 Work 都可以使用。

| 界面 | 最适合 | 没有 Skills 时的触发方式 |
|---|---|---|
| Chat | 日常问题、答案、拍摄笔记、简短反馈 | 项目指令、自动发现的 `AGENTS.md`、原生记忆与事件识别 |
| Work | 设置、大型导入、多文件整理、维护和较大复习 | 同样的持久层，加上可用时的 Skills |
| Codex | 技术性仓库设置、验证、迁移和可见 Git 审查 | 自动发现的 `AGENTS.md`、Skills 与仓库状态 |

不同套餐可能以不同方式计算 Chat 与 Work 用量。以当前账号和工作区界面为准；不要承诺 Chat 永远免费，也不要断言某项操作一定不消耗额度。若当前套餐中普通 Chat 能保留有限的 Work 额度且仍有仓库权限，应优先用 Chat 处理小型日常学习事件。

```text
验证目标与政策
→ 检查当前状态
→ 识别隐式学习事件
→ 分类学习事件
→ 整理或生成针对性问题
→ 直接写入安全变化
→ 验证并返回回执
```

不要让用户粘贴仓库、重建文件或完成当前环境已经能够完成的操作。不要要求学习者说出 Skill 名：Skills 可在有条件时改善执行，但日常闭环必须能由持久指令和记忆在没有 Skills 时继续工作。

对持久 ChatGPT Project，在获授权时把大型教材、PDF、扫描件和参考文件放入 **Sources**。Git 保存紧凑状态和出处指针。

## 仓库 Agent 路径

Codex、Claude Code、Cursor等应：

- 遵守仓库指令；
- 检查已有改动；
- 保护无关工作；
- 使用同样的整理、出题、自动化和证据规则；
- 保护私人原件；
- 汇报验证与改动文件。

使用一个主 Agent。搜索、代码执行和可视化只是能力，不是独立学习状态拥有者。

## 只读路径

没有写权限时：

- 处理当前输入或生成题目；
- 只读取真正可用的来源；
- 返回精确待写回区块；
- 明确仓库没有改变；
- 将稳定偏好与快速变化状态分开。

## 三层自动化

### 即时

当前交互内真实完成整理、出题与写回。

### 接手

每次 Agent 恢复时检查：

- 未处理 inbox；
- 到期题目；
- 等待外部反馈；
- 已解决问题的过时任务；
- 当前唯一下一步。

只有新交互与学习有关，或已开始一次计划内维护运行时，才执行这项检查。不要劫持无关对话。

### 后台

只有 Runtime 暴露真实调度器时才创建。

```text
文件里的日期或说明 ≠ 已调度自动化
真实调度任务并验证状态 = 已调度自动化
```

没有调度器时，即时与接手行为仍然可用。但要完成学习者部署，Runtime 必须创建并
验证两个必需重复后台任务；否则部署自动化明确为 `incomplete`。

## 政策与安全

读取 `learning-policy.md`。`safe-auto` 下普通、低风险、可逆状态变化无需重复确认。删除、大范围覆盖、政策变化、公开状态、私人发布、敏感身份、密钥和许可证变化前询问。

重复输入应幂等。尽量一次事件一次原子更新，并汇报能否安全撤销。

## 规则

适配执行方式，不降低产品保证。所有 Runtime 都应保持跨渠道来源、隐式学习事件识别、针对性出题、证据诚实、获授权时自动写回和用户掌控。`AGENTS.md` 与仓库状态是可移植层；原生记忆、项目 Sources、Skills 和额度处理都是运行环境适配。
