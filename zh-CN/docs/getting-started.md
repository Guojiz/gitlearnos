# 开始使用

唯一标准设置指令在[快速开始](../QUICKSTART.md)。

## 保持边界清楚

```text
GitLearnOS 模板
→ 协议、Skills、适配器、模板、示例、评测

学习者仓库（默认：私有）
→ 目标、证据、问题、作答、反馈和当前状态

Project Sources 或获授权的本地来源文件夹
→ 大型教材、PDF、扫描件、媒体和参考资料
```

不要把个人学习状态写进公开模板。远程 Git 托管是可选项；只有在需要备份、同步、
审阅、协作或发布时才添加。

## 核心版设置

1. 向有写权限的 Agent 提供模板、私有本地或远程目标，以及一个学科、目标或真实学习事件。
2. 让它读取协议，询问学习目标、学科、当前资料、获授权来源边界、RAG 存储位置和
   提供方约束，并在学习者部署前等待。
3. 让它检测真实的读写、Git、来源、记忆、Skill 和调度能力，再创建最小文件。
4. 用一个不提 GitLearnOS 的普通问题或笔记测试。
5. 检查回执：改动文件、证据、当前 Agent 工作、确实验证过的后台工作以及撤销边界。

学习者无需管理文件夹或提交。`safe-auto` 只允许安全、可撤销的写回；`preview` 提议；
`manual` 等待批准。

## 即时工作与后台工作

获授权时，当前 Agent 可以回答、整理证据并提交一次即时学习事件。`maintenance` 与
`due-review` 是外部的重复任务；提醒、Harness 会话内调度或 `requested` 任务都不能证
明主 Agent 的后台定时调用存在或已经运行。调度器无法验证时，保持交互学习可用，并把自动化报告为未完成。

## 必需检索层

大型资料放在 Project Sources 或获授权的本地文件夹。完整部署必须具备已验证的 RAG
层。RAG-Anything 是首个支持实现。Git 仍是正式事实来源，主 Agent 仍负责所有决策。
缺少已验证 RAG 时，可用的 Git 学习闭环必须标记为 `incomplete`。

另见[Git 适配器](../../adapters/git/README.md)与[迁移说明](../../MIGRATION-v2.md)。
