# GitLearnOS Agent 入口

[English](../AGENTS.md)

本文件用于帮助中文读者理解 Agent 入口。唯一正式行为规范是英文
[GITLEARNOS.md](../GITLEARNOS.md)；[中文协议](GITLEARNOS.md)是阅读辅助，
冲突时以英文为准。

开始操作前：

1. 完整阅读 `GITLEARNOS.md`；
2. 区分本公开模板与学习者的目标 Git 仓库；
3. 除非任务明显是在维护、编写文档、测试或发布公开模板，否则默认用户就是
   学习者。部署学习者系统时，一次询问学习目标、学科、当前资料、获授权来源
   边界、RAG 存储位置和模型／提供方约束；用户当前消息或已验证配置中
   已提供的事实视为已回答，不得重复询问。学习者回答前，不得安装、初始化、导入、提交或部署学习者状态。
   此门槛不阻止模板维护、文档、测试或开源发布；
4. 检查真实的读取、写入、Git、来源、RAG 和调度能力；
5. 读取目标 `gitlearnos.yml`、Dashboard、当前学科目标和最低限度的相关证据；旧版
   `learning-policy.md` 只可作为一次迁移输入；
6. 即使用户没有提 GitLearnOS 或调用 Skill，也先在内部判断当前输入是否是
   有价值的学习事件。解决眼前需求后，在 `safe-auto` 下主动执行最小的获授权
   学习操作；如果只缺一个必要事实，就简短询问一次，不能等学习者主动要求整理、
   写回、检索或下一步；
7. 所有涉及学习的请求都必须走 GitLearnOS 行为路由。可用时使用唯一 Router
   `skills/gitlearnos/SKILL.md`，再按需只加载一个操作参考文件和一个学科参考
   文件；Skills 不可用时，直接执行本文件的最小路由，不能把 Skill 可用性当作
   帮助学习者的前提。中文版本用于阅读，机器执行仍以英文为准。

操作本模板仓库时，保留已有内容。英文是正式版本；同步
`DOCUMENTATION.md` 列出的人类入口中英文。所有中文内容统一放在根目录
`zh-CN/`，翻译文件镜像英文相对路径。可安装 `skills/gitlearnos/` 包内每份
Markdown 都必须在 `zh-CN/skills/gitlearnos/` 下提供同路径中文阅读版；稳定
机器标识仍保留英文。其他纯机器执行文件不要求提供中文。

操作学习者仓库时，只根据 `gitlearnos.yml` 判断有效写入权限；旧版
`learning-policy.md` 不能改变当前权限。只有有效模式为 `safe-auto` 时，才能无需
再次确认地完成安全、可撤销的整理、出题、短期计划与 Git 写回。
`preview` 只展示拟议改动，不写入；`manual` 或配置禁用自动写入时，等待明确
批准，或返回精确的待写回内容。当前交互中的自然语言指令只覆盖本次事件并在事件
结束后失效，不会改写 `gitlearnos.yml`。始终先解决学习者眼前的需要。不能因为安装了
GitLearnOS 就保存无关对话。

Skills 用于优化执行，但不是前提。当前界面无法使用 Skills 时，直接根据这些
指令路由：整理长期证据、生成有依据的问题、评阅尝试作答、按请求辅导、保留
来源、依据证据修订模型，或维护状态。无法发现 `AGENTS.md` 的界面，应把
`templates/project-instructions.md` 用作项目指令或自定义指令。原生记忆可以
保存 `templates/native-memory-pointer.md` 中的简洁激活指针，但不能保存变化
中的学习者状态。

没有真实证据时，绝不能声称已经访问仓库、安装 Skill、完成提交、建立后台
调度、完成 RAG 导入／检索或证明掌握。完整部署必须有获授权且已验证的 RAG
知识层；RAG 无法安装或验证时，保留可用的 Git 学习闭环，并将部署标记为
`incomplete`。RAG-Anything 是首个明确支持的实现，不是唯一依赖；它是一个主
Agent 使用的工具，不是另一个 Agent，也不是正式学习状态来源。规范知识按稳定的
`<subject>/<topic>/<knowledge-point>` ID 在 Git 中整理。每次导入前都要创建或更新
Git 来源记录，写入稳定来源 ID、知识点 ID、获授权定位、RAG 文档 ID，以及重建／
删除边界。只能索引配置的逐来源授权范围，绝不能把本公开模板或示例索引为个人
知识。临时练习不得直接进入 RAG；反复出现且值得长期复用的知识先在 Git 正式整理，
再晋升到 RAG。主 Agent 已经
理解图片或片段时，应插入忠实 Markdown 或结构化表示，不重复 OCR 或视觉解析。
只有问题涉及用户特定资料或长期知识时才查询 RAG，不能每次回答都调用。
