# 鉴别诊断

[English](../../docs/differential-diagnosis.md)

GitLearnOS 已经会保存状态、更新状态、安排复测。这还不够。把第一句抱怨写进
知识缺口的 Agent 会建错学习者模型。只靠“喜欢追问”的 Agent，换一个模型就
会直接给答案。

因此鉴别诊断是协议，不是性格。

正式规则在 [GITLEARNOS.md](../GITLEARNOS.md) 和
[skills/gitlearnos/references/diagnose.md](../skills/gitlearnos/references/diagnose.md)。
本页给人读。

## 升级后的循环

旧的、不完整的循环：

```text
证据 → 知识缺口 → 练习 → 复习 → 更新
```

当信号是错误、卡住，或与旧掌握状态冲突时，必须用：

```text
信号 → 假设 → 追问 → 最佳支持诊断 → 干预 → 独立检验 → 修正
```

## 为什么第一个标签通常是错的

学习者说：“这道二次函数题我不会求最大值。”

弱 Agent 记录：知识缺口 = 二次函数最值。

稍好的 Agent 会问卡在哪，听到“不知道怎么求最大值”后，仍然写下同一个缺口。

真正原因可能是：

- 二次项系数和开口方向没有稳定联系；
- 没有顶点的图像；
- 忘了顶点公式；
- 计算失误；
- 题意误读；
- 偶然看错。

这些假设还没被分开时，表面抱怨不是知识缺口。

## 好的追问长什么样

不要问：“你为什么不会？”

要问：“对 `y = -2x^2 + 4x + 1`，先不要计算。这个抛物线开口向上还是向下？”

如果学习者说向上，那么“不会求最大值”只是表面现象。得到支持的最佳支持诊断是 `a`
与开口方向之间没有稳定联系。这才可以写入。

如果开口答对，开口方向被暂时排除；下一问应区分顶点含义、公式记忆和计算。

大约 1–3 个这样的题目是默认策略，不是聊天风格，也不是硬不变量。剩余假设
导向同一干预、学习者要求讲解、或再问不划算时，停止追问。

## 写入门槛

这里有两道门。剩余替代共享干预时可以停止追问。写 `supported` 需要某一假设
已有正向证据，且会改变教学动作的替代已被削弱。共享干预或追问预算耗尽本身
不能把标签升级为 `supported`。

偶然失误留在事件里。被否定的假设以 `falsified` 留在记录中。删掉错误标签，
比留下已否定的标签更糟。

## 矛盾是科学事件

如果仓库以前认为一元一次方程掌握较好，而今天连续两次不会移项，Agent 不能
只降低掌握度。它应该问：是遗忘、题型变复杂、含参后不会、以前的样本太窄，
还是今天状态不好——然后用一个鉴别题。

掌握是带反证义务的信念。
