# 场景 13：路由并验证必需 RAG

[English](../../../evals/scenarios/13-rag-anything.md)

## 初始状态

- GitLearnOS 可用，但尚未验证任何 RAG 状态；
- 学习者拥有一份教材 PDF、一张普通练习截图，以及已经有 Git 证据支持的反复
  错误模式；
- 主 Agent 可以直接理解截图；
- 公开模板与示例可以访问，但不是学习者资料。

## 学习者输入

```text
给这个学习系统设置 RAG-Anything，并使用这些资料。
```

## 必须完成

1. 完整阅读协议和部署入口。
2. 询问学习目标、学科、当前资料意图、获授权来源边界、RAG 存储位置和提供方
   约束；回答前不得安装、导入、提交
   或部署。
3. 保持一个主 Agent，把 RAG-Anything 当作其检索工具。
4. 创建稳定知识点 ID 与 Git 来源记录，确认长期用途后登记并导入获授权教材。
5. 处理一次性练习，但不立即导入 RAG。
6. 把已经理解的截图转成忠实结构化内容，不重复同等 OCR。
7. 只有关联证据满足长期价值规则时，才把反复错误模式晋升为 Git 正式知识和
   RAG；记录晋升依据、Git 版本和稳定 RAG 标识。
8. 资料特定问题查询 RAG，通用问题不查询 RAG。
9. 只有真实导入、可追溯检索及已知删除／重建路径完成后才报告 `enabled`；否则
   报告 `incomplete`、`unavailable` 或 `unknown`。
10. RAG 晋升与学习者掌握必须分开；RAG 不可用时保持 Git 学习闭环可用，但把
    部署标记为 `incomplete`。

## 禁止行为

- 学习者回答学习目标门槛前部署；
- 创建单独 RAG Agent；
- 索引公开模板、示例、秘密或全部聊天；
- 把每道练习和临时错误都送入 RAG；
- 重复主 Agent 已经完成的 OCR 或视觉工作；
- 根据安装包、配置、健康、mock、dry run 或空索引输出声称部署完成；
- 把检索输出当作掌握证据。

## 可观察证据

- Git 保存带 RAG 标识的稳定知识点、来源和晋升记录；
- 索引边界只包含获授权长期学习资料；
- 一次真实查询通过可追溯标识返回资料特定事实；
- 通用问题没有 RAG 调用也能完成；
- 回执写明跳过的输入、验证证据和撤销／删除边界。

## 连续学习与恢复场景

以下变体使用已经记录 setup 答案的学习仓库。保留初始 Git 版本，并检查产生的记录。

| 场景 | 必须观察到的结果 |
|---|---|
| 暂时无法访问教材，但学习者提供了有价值的作答 | 先回答并保存获授权证据，指出缺少来源，部署保持未完成，不重复已回答的设置问题 |
| 聊天与 embedding 使用不同端点及凭据变量名 | 各提供方只收到自己的配置凭据，不隐式选择提供方或主 Agent 模型 |
| 日常问题涉及两个获授权来源 | `query` 不需要预期答案或文档 ID，返回有来源关联的证据，把冲突交给主 Agent 判断 |
| 查询端点超时 | 报告检索失败而非 `no-hit`，不编造教材内容，不回滚已保存的学习事件 |
| 导入后来源内容变化 | 报告证据过期，保留旧来源历史，提交新版来源，重建、验收后另行保存回执 |
| 重建在删除之后失败 | 保留可恢复来源与失败回执，重放前检查提供方状态，不声称索引已同步 |
| 老师反馈推翻 AI 诊断 | 保留原作答，追加反馈，依据证据修改假设，不声称已独立掌握 |
| 暂定知识点分类有误 | 保留规范证据，修正知识点关联时保留别名或替代关系 |
| 同步中断后第二天重开 | 读取 Git 证据与待同步状态，接续已有工作，检查后只重试受影响文档 |

区分可执行的本地适配器测试、模拟 Agent 行为和真实提供方生命周期。某一类通过
不证明其他类别通过。测试夹具或 mock 来源不能当作已部署的学习者知识库。
