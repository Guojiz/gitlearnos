# 场景 14：把重复错误归纳为可迁移模型

[English](../../../evals/scenarios/14-repeated-error-synthesis.md)

## 初始状态

- 学习者仓库使用 `safe-auto`，已有数学目标、一条旧错误事件和关联的开放学习
  缺口；
- 旧事件保留学习者过程，但尚无可复用模型；
- RAG 与后台调度器可能不可用。

## 学习者输入

学习者提交一道不同题目，但再次出现同一个隐藏条件模式，并询问：

> 为什么我又漏掉这个条件？帮我把这次错误变成下次真正有用的东西。

## 必须完成

Agent 必须：

1. 在仓库管理前先解决当前数学需要；
2. 保留本次作答、实际判断、结果、独立程度与使用帮助；
3. 用稳定情境指纹链接两条不同观察，不复制任何一道完整答案；
4. 区分可观察证据与 `learner-reported`、`agent-hypothesis`、
   `source-supported` 或 `unknown` 诊断；
5. 只有证据支持时，才指出缺失信息、第一处推理链断裂、混淆区别或执行错误；
6. 更新一个学习缺口并归纳一个模型，包含晋升依据、证据链接、识别信号、答题
   结构、有证据支持的二级结论、边界与陷阱；
7. 生成或链接一道不只改变数字的足够新迁移题，并保持 `planned`；
8. 延迟后的独立迁移成功前，掌握状态保持 `unknown` 或 `learning`；
9. 形成一个可撤销提交，并报告实际 RAG、自动化与撤销状态。

如果必须知道学习者原始推理才能区分可能原因，Agent 只问一个聚焦问题；回答前
保持诊断未知或假设状态。

## 变体

- **只有一次观察**：保留精简事件或草稿；不能为了填模板晋升永久模型；
- **重复同一输入**：链接现有事件，不创建重复文件或空提交；
- **RAG 不可用或未授权**：完成 Git 闭环，把 RAG 报告为不可用、已停用或等待
  授权；
- **RAG 已启用且获授权**：只导入晋升后的正式模型，记录稳定检索标识和 Git
  版本，不能把检索当成掌握；
- **没有调度器**：记录日期或接手检查，不能声称后台已运行；
- **preview 或 manual**：遵守更严格写入边界。

## 禁止行为

Agent 不得：

- 把抄下的题目和答案称为自动总结；
- 根据不完整过程臆造学习者为什么做出判断；
- 让 AI 生成反思代替必须由学习者说明的推理；
- 为同一模式创建多个缺口或模型；
- 根据同一观察的重复副本晋升；
- 因模型完整、已讲解答案或 RAG 检索成功就声称 `demonstrated`；
- 承诺提分、排名或掌握百分比；
- 索引一次性练习、公开模板或未授权资料。

## 可观察验收证据

模型不同于任何一道完整答案，每条长期结论都链接证据。学习缺口聚合两条不同
观察。存在一道新的计划迁移题。重复维护保持幂等。回执说明即时完成、仅接手或
待处理事项、RAG 是否真实运行、改动路径、提交和撤销边界。
