## 常见问题

### 这是模板仓库，还是我的学习仓库？

答：这个仓库是模板。用户要创建自己的目标仓库来保存个人学习记录。

### 它能把学习数据整理到 GitHub 吗？

答：可以。它整理的是结构化学习记录，不要求上传每个原始文件。

### 可以本地使用吗？

答：可以用于测试或本地流程。但本地访问不等于 GitHub 访问。

### 需要 GitHub Actions 或 API key 吗？

答：不需要。它们只是可选高级层。

### 每次都必须说“使用 GitLearnOS”或调用 Skill 吗？

答：不必。经过引导式设置后，持久项目或仓库指令以及可用时的原生记忆，应帮助 Agent 自动注意到有价值的问题、答案、页面、笔记、反馈和结果。无关对话不应被保存。

### 应该使用 Chat 还是 Work？

答：Chat 具备已验证仓库权限时，用于简短日常学习事件；Work 用于设置、大型导入、多文件整理、维护或较大复习。Skills 是可选项，账号额度处理必须以当前套餐为准，不能作通用承诺。

### 教材和大型文件应放在哪里？

答：放入持久 Project Sources 或获授权的本地来源文件夹。Git 保存来源定位、选定片段和紧凑学习状态。

### 为什么可能要接入 GitHub？

答：用于私有备份、跨设备连续性、教师或导师审阅、共享课程材料和小组项目。共享材料要与私密学习者状态分开。

### AI 能不能直接说自己已经部署好了？

答：只有在它确实创建或修改了目标仓库文件，并且能汇报改动时，才可以这么说。

## 警示信号

如果用户可能产生下面的理解，说明文档还不够清楚：

- 把个人学习数据写进模板仓库；
- 认为本地文件权限等于 GitHub 写入权限；
- 以为首次部署必须配置 GitHub Actions 或 API key；
- 以为每个原始文件都要上传到 GitHub；
- AI 声称拥有自己没有验证过的权限；
- 认为 Agent 必须先调用 Skill 才能注意到学习；
- 认为每个大型来源文件都必须进入 Git；
- 认为 Chat、Work 和 Codex 拥有相同工具或额度规则；
- 还没创建目标仓库，就直接发题目让 AI 开始写。

## 维护规则

新增文档时，要检查它是否影响这些概念：

- 模板仓库 vs 目标仓库；
- hosted Git runtime vs 本地复刻；
- 结构化记录 vs 原始来源文件；
- AI 权限和用户手动步骤；
- 基础部署 vs 高级自动化。
