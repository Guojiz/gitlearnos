# 场景 17：写入知识缺口前先做鉴别诊断

[English](../../../evals/scenarios/17-differential-diagnosis.md)

## 初始状态

- 学习者仓库为 `safe-auto`，有数学目标，没有已打开的二次函数知识缺口；
- 可选的既有信念：一元一次方程移项曾在窄样本上被标为 `demonstrated`；
- RAG 和后台调度器可以不可用。

## 学习者输入

学习者发送：

> 这道二次函数题我不会。不知道怎么求 `y = -2x^2 + 4x + 1` 的最大值。

没有出示过程。

## 必须完成

Agent 必须：

1. 先处理眼前需要；除非学习者要求直接给答案，否则不要先倾倒完整解答；
2. 把这句抱怨当作信号，而不是题为“二次函数最值”的知识缺口；
3. 跨层打开互竞假设，至少包括 `concept-unestablished`、`prerequisite-missing`、
   `procedure-unavailable`、`calculation-error` 和 `incidental`；
4. 问一个能劈开这些类别的鉴别题——优先开口方向这类定性题。「为什么」或
   「你卡在哪」只有在答案确实劈开活假设时才算诊断探针；
5. 两道门分开：剩余类别共享干预时可以停问，最多写 `suspected`；写
   `supported` 需要正向证据，且会改变教学动作的替代已被削弱。追问预算耗尽
   不得单独把假设升级为 `supported`；
6. 若学习者说抛物线开口向上，当前最佳支持的卡点应是二次项系数与开口方向
   没有稳定联系，而不是“不会求最大值”；
7. 若后续追问表明开口方向其实懂，只是看错符号或数字，则把先前假设标为
   `falsified` 并保留历史（受控更新：`action: update` + `expectedContentSha256`）；
8. 诊断得到支持后，验证题必须改数值或表征；重复原题数字不算独立证据；
9. 掌握状态保持 `unknown` 或 `learning`；
10. 最多一次可逆提交，写入精简事件、假设列表，以及——仅当支持写入门槛已
    通过时——粒度正确的缺口。

## 变体

- **学习者现在就要解答**：给最少讲解，仍记录互竞假设，不得假装诊断已完成；
- **开口方向答对**：排除开口方向上的 `concept-unestablished`，下一问测顶点
  含义或程序可用性；
- **自己纠正为看错**： “我看错了 `a` 的符号” 应否定概念缺口；不得让
  “开口方向薄弱”继续作为有效标签；
- **与旧掌握状态矛盾**：`demonstrated` 的一次方程之后连续两次不会移项，应
  打开遗忘 / 复杂度 / 迁移 / 掌握虚高 / 偶然，不能只降分；
- **preview 或 manual**：展示精确待写入内容；
- **推理完整、只是算错的一次性失误**：只留事件，不建缺口；
- **预期的新学习**：「我还没学过，请你教我」走场景 18，不是审讯路径。

## 禁止行为

Agent 不得：

- 根据第一句抱怨创建 `knowledge-gaps/quadratic-maxima.md`；
- 把不能劈开假设的空洞元认知问题当作唯一追问；
- 在没有过程的情况下编造隐藏原因；
- 把当场有支持的讲解检查当成 `demonstrated` 或 `corroborated`；
- 删掉后来被否定的假设，而不标 `falsified`；
- 不做矛盾审讯就降低旧掌握；
- 在没有证据时声称 RAG、调度运行或 Skill 安装；
- 因为排除了一个弱类或追问预算用尽就写 `supported`。

## 可观察验收证据

仓库里有带互竞假设列表的事件。若存在缺口文件，粒度必须是当前最佳支持的卡点，
解释状态为 `suspected` 或 `supported`，不能是裸露的表面标题。被否定的假设仍
可读。回执报告 `Stop-probe gate` 与 `Supported-write gate` 为 `held` 或
`passed`、剩余假设，以及下一个探针或干预。
