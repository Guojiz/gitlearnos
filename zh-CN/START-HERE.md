# 从这里开始

[English](../START-HERE.md)

GitLearnOS 通过一个具备 Git 仓库权限的现有 AI Agent 运行。

## Agent 路径

1. 阅读[中文协议](GITLEARNOS.md)。
2. 找到学习者的目标 Git 仓库或本地工作区。
3. 除非明显是在维护或发布公开模板，否则默认用户就是学习者。询问学习目标、
   学科和当前资料，建议启用本地 RAG 知识层；回答前停止学习者安装或部署。
   模板维护、文档、测试和开源发布不受此门槛限制。
4. 引导学习者为大型学习文件选择持久项目或来源区域。
5. 检查真实的 Chat、Work 或其他 Agent 界面，以及记忆、指令、Skills、读取、写入、提交、推送、来源、RAG 和调度能力。
6. 配置持久触发，使未来学习事件无需说出 Skill 名。
7. 确认或接受学习者本地重复时间与 IANA 时区：`maintenance`（默认
   每天 21:30）与 `due-review`（默认每天 07:00），然后用真正拥有仓库能力的
   调度器创建并测试两项任务。
8. 读取目标策略、Dashboard、当前学科目标和最低限度的相关证据。
9. 环境支持 Skills 时，把完整 [`skills/gitlearnos/`](../skills/gitlearnos/)
   文件夹安装到主 Agent 的原生位置，验证发现后通过唯一 Router 路由。
10. 完成安全操作，把一次有意义的学习事件提交为一次改动，并返回规定回执。

## 重要边界

- 个人状态只能写入学习者仓库。
- GitHub 只是可选 Git 托管平台，不是核心依赖。
- Chat 与 Work 都可能可用；必须检查实际工具和限制。
- Skills 是可选项；`AGENTS.md`、Claude Code 的精简 `CLAUDE.md` 入口、项目
  指令和记忆负责跨对话触发。
- 大型原件默认放入 Project Sources 或获授权的本地来源文件夹。
- 普通聊天不是学习记录。
- 原始作答、笔记和外部反馈必须保留。
- 到期自动化应直接生成具体问题，而非只发送提醒。
- 缺少或未试运行任一必需重复任务时，部署自动化为未完成；接手时检查不能代替它们。
- 没有真实写入或调度能力时，必须诚实返回待处理内容。

可复制的初始化指令见[快速开始](QUICKSTART.md)。
