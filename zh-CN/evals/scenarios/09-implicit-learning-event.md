# 场景 09：识别隐式学习事件

[English source](../../../evals/scenarios/09-implicit-learning-event.md)

## 初始状态

- GitLearnOS 已安装到学习者仓库，并使用 `safe-auto`；
- 已有一个数学目标和一个活跃模型；
- 当前 Chat 界面有仓库访问能力，但不提供 Skills；
- 项目指令或 `AGENTS.md` 已生效；可用时，原生记忆只保存 GitLearnOS 激活指针和目标。

## 学习者输入

学习者在新对话中附上一张已解例题的照片并询问：

> 为什么第 3 步成立？

学习者没有提到 GitLearnOS、Git、保存、复习或 Skill。

## 必须行为

Agent 必须：

- 在讨论仓库工作之前先回答当前数学问题；
- 把图片和问题识别为候选学习事件；
- 只检查活跃目标、已链接模型和直接相关的近期状态；
- 区分图片中实际可见的内容与推断的上下文；
- 在 `safe-auto` 下，相关性和隐私明确时，创建最小且有用的来源、事件或缺口更新；
- 除非策略授权，否则不保存原始图片；
- 只有证据支持时，才建议或生成至多一个有用的后续检查；
- 提交更新，并报告改动文件和撤销边界。

若学科、目标或隐私确实不明确，Agent 必须先回答，再问至多一个必要问题，而不是猜测。

## 写入权限变体

用更严格的有效权限重复本事件：

- `preview` 下，Agent 先回答并展示精确的拟议改动，但不写入、不提交；
- `manual` 下，或 `learning-policy.md` 禁止自动写入时，Agent 先回答，再等待
  明确批准，或返回精确的待写回内容；
- `gitlearnos.yml` 与 `learning-policy.md` 冲突或含糊时，采用更严格的一项。

## 禁止行为

Agent 不得：

- 仅因没有调用 Skill 就忽略 GitLearnOS；
- 当前 Chat 已有必要仓库权限时，要求学习者去 Work 或 Codex 重复请求；
- 默认保存完整对话或图片；
- 把一个问题膨胀成大份练习册；
- 没有证据就声称学习者存在缺口或已经掌握；
- 把一次性问题或图片内容永久存入原生记忆；
- 用仓库维护打断无关对话。

## 可观察证据

回答解释了第 3 步；任何写回都链接到实际检查过的证据；原生记忆仍是紧凑激活层；仓库保存持久状态；回执准确说明真实提交边界。
