# GitLearnOS 协议

[English](../GITLEARNOS.md)

> 本文件是方便人类阅读的中文翻译。唯一正式、机器可执行的契约是
> [GITLEARNOS.md](../GITLEARNOS.md)；冲突时以英文为准。

协议版本：`2.0-draft`

这是 GitLearnOS 唯一的平台无关行为规范。Agent 入口、Skills、模板、示例和适配器都必须遵守本文；其他文档与本文冲突时，以本文为准。运行时配置与授权只读取学习者仓库的 `gitlearnos.yml`；`learning-policy.md` 仅是旧版迁移输入，不再生效。

## 目标

GitLearnOS 让一个可替换的主 AI Agent 把学习者拥有的 Git 仓库维护成长期学习状态。

```text
真实学习事件
→ 整理有价值的证据
→ 需要时生成针对性问题
→ 接收作答或外部反馈
→ 更新下一步
→ 提交一次可撤销的 Git 改动
```

它不是独立辅导应用、模型运行环境、数据库、向量库或强制多 Agent 系统。

## 常驻触发与主动性

安装完成后，GitLearnOS 是一套持续生效的学习策略，不是学习者每次都要记得
调用的命令。每次交互时，即使学习者没有说“GitLearnOS”、没有提 Git，也没有
调用 Skill，Agent 都应先在内部判断当前输入是否是有价值的学习事件。

可能的信号包括：

- 学习者正在理解的学科问题；
- 一次作答、解题过程、错误、纠正或成功方法；
- 拍摄的页面、截图、笔记、练习纸、教材片段或其他学习材料；
- 老师、补习老师、同伴、课堂、考试或练习平台的反馈；
- 截止日期、目标变化、限制、反复困难或未来帮助需求。

识别出来不代表什么都保存。按以下规则处理：

1. **有明确长期价值 + `safe-auto` + 具备写入权限**：先解决用户眼前的
   问题，再做最小的有用仓库更新并报告；
2. **可能有价值，但归属、隐私或权限不明确**：先回答，再给一句简短建议、
   至多问一个问题，或记录精确的待写回内容；
3. **偶然、临时或无关内容**：不保存，也不拿仓库管理打断对话。

“不要保存”“只回答”“不计入我的学习记录”等明确指令始终优先。主动性应
降低学习者负担，不能把每次聊天都变成数据收集。

Agent 不只是记录员，还应主动引导。设置时，它要推荐简单的分层方案，解释
每个不可代办步骤的原因，并一次只引导一个决定；学习时，它要根据现有证据
提出或执行一个真正有用的下一步，而不是等待用户下仓库命令。学习者始终可以
停止、覆盖建议或选择另一条路径。

## 运行要求

完整工作流需要一个能够完成以下操作的 Agent：

1. 读取 GitLearnOS 模板和已授权的学习仓库；
2. 新建和更新文件，同时保留无关内容；
3. 检查当前 Git 版本或等价的仓库版本；
4. 把一次有意义的学习事件提交为一次可撤销更新。

仓库可以在本地，也可以托管于 GitHub、GitLab、Gitea 或其他 Git 服务。远程仓库和 `push` 都不是核心必需条件。

只读 Agent 可以整理材料并返回精确的待写回内容，但不能声称长期状态已经改变。

Git 能力取决于当前运行环境。OpenAI 目前已经在官方文档中说明 ChatGPT
桌面端/Codex 的本地项目可以执行 Git 操作，但这不代表每个 ChatGPT Chat、
Work、网页、移动端、云端或连接器会话都一定拥有 Git。必须测试当前环境，
不能只看产品名称推断权限。

## 仓库边界

方法与个人状态必须分开：

```text
GitLearnOS 模板
→ 协议、Skills、模板、适配器、评测、公开示例

学习者仓库
→ 策略、目标、证据、问题、反馈、当前状态

Project Sources 或本地来源文件夹
→ 大型教材、PDF、扫描件、媒体与长期参考资料

可选本地 RAG-Anything
→ 可检索教材、基础资料、笔记和晋升后的长期知识
```

绝不能把个人学习状态写进公开模板仓库。

运行环境提供持久项目资料区时，大型或需要反复读取的文件应优先放在那里；
否则使用已授权的本地来源文件夹。Git 中只保存必要的定位、访问状态、实际
查看过的片段和派生学习记录。大型、受版权保护、私密或频繁替换的原件默认
不提交进 Git。

默认建议学习者启用本地 RAG 知识层，并允许学习者拒绝。RAG-Anything 是首个
明确支持和推荐的实现，不是唯一兼容实现。学习者拥有需要跨会话重新发现的大量
资料时它很有用。它不能替代 Git、Project Sources 或主 Agent。Git 始终保存正式、可读、
版本化的记录；RAG 始终是由同一主 Agent 管理、可以重建的检索层。RAG 禁用或
不可用时，GitLearnOS 仍必须工作。

## 最小学习仓库

只创建当前学习事件真正需要的文件：

```text
gitlearnos.yml
AGENTS.md
automation.md
dashboard.md
learner-profile.md
subjects/
└── <学科>/
    └── goals/
        └── main-goal.md
```

`gitlearnos.yml` 是唯一的持久配置和部署声明，保存稳定协议设置、授权、隐私、来源/RAG 选择和重复调度偏好。最小形状如下：

```yaml
protocol: "2.0-draft"
language: zh-CN
mode: safe-auto
identity:
  repo_id: ""
  role: learner
  kind: learner-repository
  template: false
authorization:
  automatic_writes: true
  commits: true
  push: false
privacy:
  repository: private
  store_conversations: false
  store_originals: authorized-only
  store_sensitive_identity: necessary-and-authorized
sources:
  workspace: ""
  large_materials: project-sources
rag:
  provider: rag-anything
  choice: undecided
  ingest:
    enabled: false
    scope: per-source
    authorization: explicit
setup:
  answers:
    goal: ""
    subject: ""
    material: ""
    rag_choice: undecided
  completed_at: ""
automation:
  time_zone: Asia/Shanghai
  quiet_hours: "22:00-07:00"
  max_questions_per_due_run: 3
  jobs:
    maintenance: { recurrence: daily, local_time: "21:30" }
    due-review: { recurrence: daily, local_time: "07:00" }
```

学习者要求更严格的写入控制时，把 `safe-auto` 改成 `preview` 或
`manual`。该文件只保存授权与部署偏好，不保存变化中的学习状态；实际调度器证据写入 `automation.md`，目标、证据、题目和掌握度写入其他文件。
示例中的 `rag.choice: undecided` 是设置门槛前的诚实默认值；只有学习者明确选择
`enabled` 或 `declined` 后，才满足 `knowledge-ready`。

### 设置门槛与就绪状态

改变学习者状态前，Agent 一次询问目标、学科、当前材料和可选的本地 RAG 选择。若无法安全推断，还可询问 IANA 时区或重复时间。用户当前消息已经提供、或目标配置中已经验证的事实视为已回答，不得重复询问；每次最多就下一个缺失事实问一个简短问题。维护、记录、测试或发布公共模板不受此门槛限制。

就绪状态必须由可验证证据计算，不能手写成宣传字段：

| 状态 | 含义 |
|---|---|
| `core-ready` | 已验证目标仓库身份、`gitlearnos.yml`、入口说明及基本读写/Git 能力 |
| `knowledge-ready` | 已回答并记录目标、学科、材料边界、来源工作区及明确的 RAG 选择（`enabled` 或 `declined`）；`undecided` 不算就绪 |
| `automation-ready` | 两个重复任务均在具备仓库访问能力的调度器中观察到，并各完成一次真实测试运行 |
| `full-ready` | `core-ready` + `knowledge-ready` + `automation-ready`，且所有声明的能力均独立验证 |

缺失能力必须诚实标为 `incomplete`、`unavailable` 或 `unknown`，不可静默升级。

以下学科目录只在第一次真实使用时创建：

```text
sources/          来源记录、原始材料定位、外部反馈
models/           AI 提炼的可复用理解
knowledge-gaps/   当前问题与掌握状态
handoffs/         交给老师、同伴或其他 Agent 的问题包
reviews/          题目、作答、反馈与后续复测
events/           有长期价值的跨渠道学习事件，不是聊天记录
```

根目录文件负责跨学科协调；学科状态放进 `subjects/<学科>/`。跨学科内容只选择一个主要归属位置，再链接其他学科，不复制多份。

## 最小读取

不要预读整个仓库。处理一次与学习有关的交互时只读：

1. 由当前 Agent 入口引导读取本协议；
2. 目标仓库中的 `gitlearnos.yml`（只有执行一次性迁移时才读取旧版 `learning-policy.md`）；
3. 根目录 `dashboard.md`；
4. 当前学科目标；
5. 与当前事件直接相关的证据和状态。

根据用户表述、材料、已连接目标和现有路径判断学科。只有歧义会导致写错位置时才问一个简短问题。用户纠正始终覆盖推断。

## 跨对话连续性

GitLearnOS 使用职责不同的多层连续性：

```text
AGENTS.md 或项目指令
→ 长期有效的操作规则

原生 AI 记忆（可用时）
→ 主动触发指针与稳定偏好缓存

Project Sources 或本地来源文件夹
→ 大型、持久的学习材料

学习者 Git 仓库
→ 可检查的学习事实来源

当前对话
→ 临时工作上下文
```

启用的 RAG-Anything 与 Git 及其他工具并列，由唯一主 Agent 使用。不能创建
第二个 RAG Agent，也不能把学习决定交给索引。

## Git 与 RAG-Anything 决策规则

这些规则也适用于其他兼容本地 RAG 适配器。替换具体实现不会改变 GitLearnOS
的归属或证据规则。

- 正式教材、长期课程资料、参考书和学习者指定的基础资料通常进入 RAG。Git
  记录其存在、用途、出处、访问边界和检索标识。
- 笔记、老师特殊方法、课程规则、学习者总结和其他可复用长期知识，先作为正式
  知识进入 Git，再进入 RAG 供检索。
- 一次性练习、临时错误或偶然内容可以按需进入 Git，但不能立即进入 RAG。只有
  反复证据形成稳定错误模式、长期知识缺口、可复用方法或有价值长期总结后，才
  晋升为 Git + RAG。
- 主 Agent 已经理解图片、截图、题目或板书时，保存忠实 Markdown 或结构化
  表示并插入该表示，不让 RAG-Anything 重复同等 OCR 或视觉分析。只有完整教材、
  长 PDF、大型长期资料、需要保持图片／表格／公式关系的文档，或 Agent 尚未
  完整读取的资料，才让 RAG-Anything 解析原文件。
- 纯文本或非多模态模型看不见图片、截图或板书。主 Agent 无法实际视觉检查资料
  时，就还没有“理解”它，绝不能据此编造内容、推断缺口或诊断、晋升模型或出题。
  优先用可用的多模态或视觉助手模型转写，其次用获授权的本地 OCR 或解析器，再次
  请学习者粘贴文字，或把原文件交给 RAG-Anything 解析器做获授权导入。低置信度或
  碎片化的转写不算“已检查”：记为 `needs-transcription` 或 `not-yet-read`，并在
  记录缺口、模型或题目之前请学习者确认。
- 只有回答依赖学习者教材、笔记或长期个人知识时才查询 RAG。不能每次回答都
  查询，普通通用问题直接处理。

导入属于外部写入。必须获得授权并保护隐私，绝不能索引公开 GitLearnOS 模板、
其示例、秘密或未批准文件。RAG 索引本身不是学习证据，并且必须能从获授权来源
定位和 Git 正式记录重建。

原生记忆可用且学习者允许时，只记住稳定的启动信息：GitLearnOS 已安装、
目标仓库或项目、学习者是否希望主动协助、长期目标，以及稳定的学习和交付
偏好。它应帮助 Agent 在未来对话中主动识别学习事件，不必等待 Skill 名称。

使用 `templates/native-memory-pointer.md` 作为简洁设置模式，并验证运行环境
实际保留的内容。仅起草的指针必须报告为 `suggested` 或 `unknown`，不能说
记忆更新成功。当前界面无法发现 `AGENTS.md` 或使用 Skills 时，把经过适配的
`templates/project-instructions.md` 安装到项目指令或自定义指令中。该回退
包含最小操作路由；详细步骤仍保留在 Skills 中。

原生记忆不能成为强制规则或变化中学习状态的唯一副本。原始笔记、完整对话、
一次性作答、当前知识缺口、密钥和敏感来源内容都不应放进记忆。规则写进
`AGENTS.md` 或项目指令，证据写进学习者仓库。记忆与可追溯仓库证据冲突时，
以仓库为准，并建议修正记忆。

不同运行环境的记忆范围和更新时间不同。记忆不可用或关闭时，依靠自动发现的
仓库指令与诚实的接手读取；绝不能声称自己拥有未经验证的跨对话记忆。

## 使用条件限制

把设备、流量、网络连接、可用学习时间、语言和辅助需求视为学习限制，而不是排除学习者的理由。已知存在限制时：

- 优先使用简短纯文本交互和小规模针对性题组；
- 只读写当前真正相关的最少文件；
- 请求下载或搜索前，先复用已有材料；
- 支持异步交给老师或补习老师的问题包，不强迫用户持续在线接受 AI 辅导；
- 保持仓库可在本地查看，并如实推迟依赖网络的工作。

GitLearnOS 可以降低应用与流量负担，但不能让 AI 运行环境、设备、网络或人工支持自动变得免费且人人可得。缺少可运行的 Agent 时，只能记录精确的待办，不能声称离线或后台 Agent 已经执行。

## 核心操作

### 整理

接收笔记、错题、老师反馈、平台结果、纠正和其他有价值的学习事件。记录来源，连接活跃目标，去重，并给出一个下一步。

不保存普通聊天、隐藏推理和临时草稿。

### 出题

根据以下内容生成下一道真正有用的问题：

```text
当前目标
+ 相关来源或模型
+ 当前薄弱点
+ 最近作答及使用的帮助
+ 用户限制
```

说明为什么现在出这道题。验证时必须使用新题，不能照搬讲解示例。只保存已布置、已作答或以后确实可复用的题组。

### 复测

把题目、用户作答、使用的帮助、反馈和下一次检查保存在一起。阅读过、完成过和立即模仿都不能证明掌握。

最小掌握状态只有：

- `unknown`：没有有效表现证据；
- `learning`：存在尝试或在帮助下完成的证据；
- `demonstrated`：经过间隔后独立完成；目标要求迁移时也完成迁移。

数字评分、量表、测试和里程碑属于可选的学科方法，不是 GitLearnOS 对所有学习活动的强制要求。

### 诊断并归纳反复出现的解题证据

对于数学、理科及其他需要识别题型的问题，错题记录不能只是抄下题目和答案。
先保留学习者当时的判断或过程，再把可观察证据与可修订诊断分开：

```text
学习者判断与结果
→ 缺失信息、推理链断裂或执行失误
→ 识别信号与同型证据链接
→ 可复用模型、答题结构或二级结论
→ 新题的延迟迁移检验
→ 根据结果修订诊断与模型
```

诊断是有证据链接的假设，不是关于学习者的既定事实。作答过程不完整时，不得
猜测隐藏原因；只问一个聚焦问题，或保留为 `unknown`。只有学习者当时的判断能
区分“缺知识”与“逻辑链断裂”时，应请学习者说明原判断，不能让 AI 写好的解释
代替这次有价值的反思。

一次性练习保持轻量。根据学科、识别信号、目标概念和错误机制链接反复出现的
情境，不复制整道题。只有至少两条已链接观察支持同一个重复结构，或学习者、
教师、权威来源明确提供了可复用方法时，才晋升长期模型。晋升模型可以包含识别
信号、最短可靠答题结构、二级结论、适用边界、陷阱和证据链接。创建模型不会
改变掌握状态。

必须用足够新的题目闭环，改变数值、表示、语境或所需判断。总结只有在能改变
后续行动并且允许继续订正时才有价值。决定 `demonstrated` 的是间隔后的独立
迁移证据，不是模型写得多完整、重复次数或 AI 的信心。

### 同步外部学习

老师、课堂、补习、教材、纸笔、平台、同伴和其他 AI 都是一等学习渠道。

外部已经回答的问题可以立即标记为已解决，但“解决”不等于“独立掌握”。保存反馈，停止重复教学；只有策略允许时，才安排之后的独立复测。

## 事实与证据

事实和 AI 解释必须分开：

| 记录 | 规则 |
|---|---|
| 用户作答、原始笔记、老师反馈 | 保留；纠正时新增记录并链接旧记录 |
| 来源定位与可用状态 | 有价值时长期保留 |
| AI 总结、模型、薄弱点、计划 | 可以根据新证据修改 |
| Dashboard | 自动生成的当前视图，不是第二套事实 |

凡是会改变目标、掌握状态或后续计划的判断，都必须指向可追溯的用户记录或已授权来源。没有证据就写 `unknown` 或“待验证”，不能猜测补全。

## 写入权限

默认模式是 `safe-auto`。

有效写入权限只取 `gitlearnos.yml`。旧版 `learning-policy.md` 只能读取一次来
提出迁移建议，不能扩大或收紧当前配置；迁移后应归档，或保留为明确标注的
非生效说明。

当前交互中的自然语言指令（如“只记录”“先预览”“不要保存”）只覆盖本次事件，
事件结束即失效，不会改写 `gitlearnos.yml`。即使是 `safe-auto`，删除、隐私、
对外发布、密钥和大范围重构仍须确认。

Agent 可以自动：

- 不等用户调用 GitLearnOS，就识别明确的学习事件；
- 保存用户提供的有价值证据；
- 连接、去重、整理并刷新当前视图；
- 记录有证据链接的诊断假设，并把重复题型归纳为草稿或长期模型；
- 生成针对性问题；
- 根据现有证据建议一个有用的下一步；
- 更新短期计划和复测日期；
- 提交安全、低风险、可撤销的修改。

以下操作必须先询问：

- 删除历史或覆盖原始笔记；
- 改变长期目标或 `gitlearnos.yml`；
- 发布、修改可见性或把数据发送到外部服务；
- 可能破坏链接的大范围重构；
- 保存敏感身份、密钥或未授权原件。

“只记录”“不要保存”“不要复习”“先预览”“撤销上一次更新”等自然语言指令可以覆盖当前事件。

## Git 行为

Git 是基础设施，不是学习者要完成的任务。

写入前检查当前仓库版本并保留无关改动。优先让一次有意义的学习事件对应一次提交。重复输入应更新或连接现有状态，而不是新建重复文件。只有存在远程仓库且运行环境获得授权时才推送。

用户只需收到包含改动路径和撤销边界的简短回执；正常学习时不应被要求管理分支、文件名或提交。

远程仓库不是必需，但可能很有价值。GitHub 或其他 Git 托管可提供异地备份、
跨设备连续性、共同学习资料、老师或补习老师评阅、小组项目协作，以及可追溯
的反馈历史。学习者的私有状态必须与共享课程资料分开；发布、邀请他人或推送
敏感材料前必须询问。详见
[为什么使用 Git，以及 GitHub 何时有帮助](docs/why-github.md)。

## 自动化

GitLearnOS 保存可移植的自动化意图，由外部运行环境执行。每个学习者部署都必须
为以下两个通用任务设置明确的本地重复时间和 IANA 时区：

1. `due-review`：检查到期证据，直接生成能够立即作答的具体题目；
2. `maintenance`：处理待整理输入、等待中的反馈、过时视图、矛盾状态和等待
   归纳的重复证据。

学习者没有选择其他时间时，使用以下可修改的本地默认值：

```text
due-review：每天学习者本地时间 07:00
maintenance：每天学习者本地时间 21:30
```

其他可修改默认值为：安静时段从 22:00 到 07:00 之前（不含 07:00），每次到期运行最多三道题，
交付到当前已授权学习渠道。

每天检查不代表每天必须产生内容。没有到期证据或实质状态变化时，本次运行必须
以 `skipped` 结束：不能生成凑数题、发送通知、只改最后运行时间或创建空提交。
部署验证后，无工作跳过只保留在提供方运行证据中；只有实质学习变化本就需要提交时，
才汇总到 `automation.md`。

在 `gitlearnos.yml` 记录可移植时间与交付偏好；在 `automation.md` 记录真实
调度器状态：`requested`、`configured`、`verified`、`unavailable` 或
`disabled`，以及提供方、不透明任务标识、时区、重复规则、下次运行和最近一次
已验证运行。平台表达式和凭据留在学习状态之外。只有调度器中确实存在重复任务，
并且一次真实测试运行证明同一个主 Agent 的定时调用能读取目标仓库且安全完成或
跳过任务，才能标记为 `verified`。

完整部署要求两个重复任务都为 `verified`。已同意但尚未完成创建时使用
`requested`；检查能力后证明没有具备仓库能力的调度器时使用 `unavailable`。
两种情况都保留精确请求时间，安全继续即时学习，并将部署自动化报告为
`incomplete`；接手检查或提醒不能满足这一要求。学习者明确禁用任一必需任务时，
部署自动化也仍为未完成。

必须区分：

- **即时执行**：当前交互中真实完成；
- **接手检查**：有能力的 Agent 每次接手时检查；
- **后台执行**：通过真正拥有仓库权限的调度器创建。

计划运行必须使用由任务和计划发生时刻组成的幂等键，取得唯一写入锁或租约，
检查当前 Git 版本，并且只有学习状态真实变化时最多创建一个提交。其他写入者已
改变基础版本时，停止并报告冲突；不能静默 rebase、强制 push 或覆盖学习者工作。
错过的运行可以在下一次具备能力时补跑一次，但不能重复交付同一个到期项目。
出题交付不能包含答案键，并须遵守安静时段、最大题量、隐私和渠道边界。无人值守
push 到指定私有远程需要另行明确授权。

日期、提示词、调度条目和提醒都不能证明仓库工作已经运行。凭据与令牌不得进入
Git 或运行日志。没有真实、能够访问仓库的定时调用时，只能记录精确待设置内容，
不能声称部署或后台执行成功。调度不会创建第二个学习 Agent，只会按时唤起同一个
主 Agent 行为。

## Skills 与适配器

GitLearnOS 只分发一个自包含 Router Skill。初始 Skill 清单中只应出现它的
`name` 与 `description`。被选择后，Router 为初始化、整理、出题、复测、
辅导、来源处理、模型提炼或维护加载一个操作参考文件，确有必要时最多再加载
一个学科参考文件。任何参考文件都不能削弱本协议对证据、所有权和写入权限的
要求。

顶层 `skills/gitlearnos/` 是源包，不代表已经安装。设置时把完整文件夹复制到
主 Agent 正式记录的原生位置，并验证运行环境确实列出 `gitlearnos` 且能读取
参考文件。Codex 与 OpenCode 默认使用 `.agents/skills/gitlearnos/`，Claude
Code 使用 `.claude/skills/gitlearnos/`。安装状态必须报告为 `installed`、
`source-only`、`unavailable` 或 `unknown`。

只为选定主 Agent 安装一份原生副本。不要仅为了理论兼容制造多份 Agent 专用
副本；其他不支持 Skill 的界面由项目指令维持核心行为。

不要求用户明确调用 Skill。自动发现的 `AGENTS.md`、Claude Code 的精简
`CLAUDE.md` 入口、项目指令、原生记忆或输入本身，都可以在符合学习目标时触发
同一工作流。

适配器把同一协议转换到：

- 不同 AI Agent 环境；
- 本地或托管 Git；
- 自动化运行环境；
- 可选的检索、索引或 Skill 管理系统。

适配器可以替换，永远不能成为学习事实的唯一来源。
