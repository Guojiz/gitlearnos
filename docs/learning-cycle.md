# Learning Cycle

GitLearnOS is not only a review system.

Review is the ground layer of learning. The point is to return to old material and create new understanding from it.

## Principle

Learning should follow this cycle:

```text
learn
→ attempt and preserve the judgment
→ diagnose missing information or the first broken reasoning link
→ link same-pattern evidence
→ synthesize a model, answer structure, and supported conclusions
→ recall and apply it later in a sufficiently new task
→ revise the diagnosis and model from feedback
```

This is a cycle, not a pipeline that every exercise must enter. A normal
one-off item stays lightweight. Repeated observations or an explicitly reusable
method justify synthesis; delayed independent transfer justifies mastery.

## Review is not the end

Review does not mean repeating old answers.

A good review should produce:

- a cleaner model;
- a better recognition cue;
- a new problem variation;
- a stronger explanation;
- a connection to another topic;
- a new practice item.

A copied solution is not a model. A useful synthesis preserves the learner's
original decision, links its evidence, states recognition cues and limits, and
changes what the learner or agent does on a later task.

## Evidence-informed, not outcome-promising

Retrieval practice and delayed checking can support long-term retention, and
varied practice can improve discrimination among problem types. These findings
do not justify promises about a learner's rank, score gain, or a fixed mastery
percentage. Explanation, summary, model creation, and RAG retrieval are inputs
to learning—not evidence of mastery.

Primary research: [Roediger and Karpicke on delayed retention](https://doi.org/10.1111/j.1467-9280.2006.01693.x),
[Karpicke and Roediger on repeated retrieval](https://doi.org/10.1126/science.1152408),
and [Rohrer and Taylor on mixed mathematics practice](https://doi.org/10.1007/s11251-007-9015-8).

## Warm the old, create the new

Old material should be used as fuel for new learning.

The AI should ask:

1. What did the user know before?
2. What was forgotten?
3. What pattern can be extracted?
4. What new question can be generated?
5. What should be linked to the current goal?

## Repository behavior

The repository should not freeze old knowledge.

It should let files evolve:

- original answers and feedback stay preserved;
- AI-derived cards and models can be revised or merged from linked evidence;
- gaps can be resolved while mastery stays separately evidenced;
- inactive items can be archived without erasing history;
- review items can generate new tasks.

## Practical rule

The system reviews old material so the user can learn something new from it.
