# GitLearnOS — AceSAT Build for Impact

[English](../../docs/acesat-build-for-impact.md)

## 问题

资源不足的公立学校学生可能拥有认真负责的老师和有用的免费材料，却缺少持续、个性化的跟进。练习结果、课堂讲解、纸质笔记与偶尔的补习彼此分散；下一次学习往往不知道哪个错误仍然重要、已经得到过什么帮助，以及进步能否保持。

## Agent

GitLearnOS 把一个由学习者拥有的 Git 仓库变成一个可替换主 AI Agent 的长期状态：

```text
真实练习或老师反馈
→ 有证据的薄弱点
→ 最小但有价值的下一道问题
→ 保留作答与使用的帮助
→ 之后独立复测
→ 可撤销 Git 写回
```

Agent 不只是回答。它在用户授权的策略范围内整理证据、选择下一项任务、调整题量和交付方式、获得外部帮助后停止重复讲解、准备聚焦的老师问题包，并更新未来检查。长期目标和高影响操作仍由学习者控制。

## 演示

可运行 SAT 演示中的虚构学生共用手机、限制移动流量、每次只能学习 20 分钟，也不能依赖持续付费辅导。面对一条经过清理的词汇语境错误，Agent 会：

1. 保留用户原话与缺失的证据；
2. 建立范围很窄的薄弱点，而不是给整体能力贴标签；
3. 复用本地材料，只交付一道纯文本问题；
4. 写回答案、使用的帮助、反馈与下次检查；
5. 没有证据时拒绝声称掌握或后台自动化已经执行。

从[三分钟可运行演示](../LIVE-DEMO.md)开始。

## 可能产生的帮助

- 用简短、有证据的问题包集中使用稀缺的老师时间；
- 学生无需管理 Git、文件夹或再学习一个新应用；
- 学校、图书馆、纸质材料、老师和开放资源都能继续使用；
- 后续题目针对已观察到的薄弱点，而不是生成大批通用练习；
- 原始作答与反馈可供检查，不会被 AI 总结静默替换。

这些是预期效果，不是已经测得的结果。学校试点应测量：延迟独立作答正确率、重复错误率、复测完成率、准备老师帮助所需时间、单次学习事件流量，以及学生对存储记录的控制程度。

## 可访问性与成本边界

核心开源、纯文本优先、兼容本地 Git，不强制数据库、向量服务、独立服务器或常驻进程。它支持短时异步交互、少量增量读取、已有本地材料与老师交接。

当前本地 Project 或会话具备已验证仓库权限时，ChatGPT Chat 或 Work 都可以直接完成文件与 Git 闭环。Skills 是可选项；持久项目或仓库指令与记忆让日常交互保持触发。学生正常使用时不需要 GitHub；GitHub 在这里用于公开的比赛提交。其他情况下，只有用户主动选择同步、备份、协作或发布时才需要远程仓库。

它并不是零资源技术。Agent 真正工作时，学生仍然需要某种设备和可用 AI 运行环境。网络、AI 价格、学校政策、无障碍需求和 Git 初始化都必须由真实学生测试，不能靠推测忽略。只读或暂时离线时必须报告待执行工作，不能说成自动化已经完成。

## 技术实现

- 唯一 Agent 契约：`GITLEARNOS.md`；
- 可复用路由与操作 Skills：`skills/gitlearnos*/`；
- 学习状态：纯 Markdown 与少量 YAML；
- 版本和撤销：本地或托管 Git；
- 可选调度：`due-review` 与 `maintenance`，只能由真实授权的运行环境执行；
- 评测：拒绝虚构掌握、权限、调度与写回的行为场景。

不强制任何特定模型、API、云平台、数据库或 Git 托管商。

## 原创性与本次构建范围

参赛作品是比赛期间开发的 Git 原生 v2 Agent 协议、受限使用条件 SAT 演示、影响说明与评测。公开 Git 历史仍完整保留，包括此前存在的项目记录；提交不会把旧工作伪装成本次新建。
